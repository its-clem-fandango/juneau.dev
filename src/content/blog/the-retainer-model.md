## The Project Model Is Broken

Here's how project-based development usually goes:

1. You scope a project. It takes three meetings and a 20-page requirements doc.
2. Development starts. Requirements change (because they always do).
3. Change requests trigger scope negotiations. Everyone gets frustrated.
4. The project "finishes." You get a handoff document and a codebase you're now responsible for.
5. Three months later, something breaks and the original team is gone.

This model optimizes for the wrong thing. It treats software like a building — something you construct once and then inhabit. But software is alive. It needs ongoing care, or it decays.

That's not a project. That's a partnership.
